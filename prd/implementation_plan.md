# Технический Стек и Архитектура Базы Данных

## 1. Технический стек

### 1.1 Backend (Логика и API)
*   **Язык программирования:** Python 3.11+
    *   *Почему:* Лучшая экосистема для работы с LLM, удобен для написания ботов.
*   **Фреймворк для бота:** `aiogram 3.x`
    *   *Почему:* Современный асинхронный фреймворк для Telegram API на Python. Поддерживает Форумы (Topics).
*   **LLM-интеграция:** Самописная логика агента на Python — прямые вызовы API (Tool Calling, Structured Output). Без LangChain и аналогичных фреймворков.

### 1.2 База Данных
*   **СУБД:** SQLite
    *   *Почему:* Достаточно для MVP — нет необходимости в отдельном сервере БД. Легко развернуть, нулевая конфигурация.
*   **ORM:** `SQLAlchemy` + `Alembic` (для миграций).

### 1.3 Интеграции
*   **LLM Provider:** Google Gemini API.
    *   **Основная модель (MVP):** `gemini-2.5-flash` — быстрая, дешёвая ($0.30/$2.50 за 1M токенов), контекст 1M, бесплатный тир для разработки. Поддерживает Tool Calling и Structured Output.
    *   **Резервная модель (Fallback):** `gpt-5.4-mini` (OpenAI). В архитектуру закладывается возможность использования резервного провайдера.
    *   **Конфигурируемость:** Выбор активной модели (Gemini или OpenAI), а также их параметры (например, temperature, api_key), задаются через единый конфигурационный файл (например, `.env`), что позволяет переключаться между ними без изменения кода.
*   **Google Sheets:** `gspread` + Google Service Account для авторизации.

### 1.4 Контекст диалога (MVP)
*   На этапе MVP вся история диалога передается в LLM целиком (без суммаризации).
*   История хранится в SQLite (таблица `messages_history`).
*   Контекстное окно Gemini 2.5 Flash (1M токенов) позволяет передавать полную историю без ограничений.

## 2. Структура Базы Данных (Схема SQLite)

### Таблица 1: `clients` (Клиенты/Компании)
Сущность бизнеса, который покупает рекламу.
*   `id` (INTEGER, Primary Key, AUTOINCREMENT)
*   `name` (TEXT) — Название компании (например, «ООО Ромашка»).
*   `inn` (TEXT, UNIQUE, Nullable) — ИНН (если клиент его назвал).
*   `created_at` (TEXT, ISO 8601)
*   `notes` (TEXT, Nullable) — Заметки для админа.

### Таблица 2: `representatives` (Представители / Контакты)
Конкретные люди (менеджеры, бухгалтеры), которые пишут в бота.
*   `telegram_id` (INTEGER, Primary Key) — ID пользователя в Telegram.
*   `client_id` (INTEGER, Foreign Key → `clients.id`, Nullable) — NULL, пока представитель не «сматчен» с компанией.
*   `username` (TEXT, Nullable) — @username.
*   `first_name` (TEXT)
*   `role` (TEXT, Nullable) — Например, «бухгалтер» или «менеджер».

### Таблица 3: `admin_topics` (Темы в Форуме)
Связывает представителя с веткой обсуждения в админской группе.
*   `topic_id` (INTEGER, Primary Key) — ID темы (`message_thread_id`) в супергруппе.
*   `telegram_id` (INTEGER, Foreign Key → `representatives.telegram_id`, UNIQUE) — Одна тема = один человек.
*   `status` (TEXT) — Статус диалога: `active`, `waiting_human`, `closed`.

### Таблица 4: `messages_history` (История сообщений)
Память бота для передачи контекста в LLM.
*   `id` (INTEGER, Primary Key, AUTOINCREMENT)
*   `telegram_id` (INTEGER, Foreign Key → `representatives.telegram_id`)
*   `role` (TEXT) — `user` (клиент), `assistant` (бот), `admin` (администратор).
*   `content` (TEXT) — Текст сообщения.
*   `created_at` (TEXT, ISO 8601)

## 3. Интеграция с Google Таблицами

Бот работает с одним Google Spreadsheet документом, который является **единственным источником правды** для календаря и задач по документам.

### 3.1 Лист «Календарь (Слоты)»
| Дата | Время | Статус слота | Клиент | Сумма | Срок | Ссылка на диалог |
|------|-------|--------------|--------|-------|------|------------------|
| 15.09 | 10:00 | Свободен | — | 3000 | 24ч | — |
| 16.09 | 18:00 | Забронирован | ООО Ромашка | 5000 | 24ч | [t.me/c/123/456] |

*   **Чтение:** Бот отфильтровывает слоты со статусом «Свободен» и предлагает их рекламодателям.
*   **Запись:** При бронировании бот переводит статус в «Забронирован», заполняет данные клиента и вставляет прямую ссылку на Topic (тему) с этим клиентом в Telegram.

### 3.2 Лист «Задачи (Документы)»
| Дата и Время | Статус | Тип документа | Название Клиента | ИНН | Контактное лицо | Ссылка на диалог |
|--------------|--------|---------------|------------------|-----|-----------------|------------------|
| 18.03 14:30 | В очереди | Счёт + Договор | ООО Ромашка | 1234567 | @username (Анна) | [t.me/c/123/456] |

*   **Запись:** ИНН и Название Клиента извлекаются ботом из диалога, либо берутся из базы данных (если клиент общался с ботом ранее). Бот добавляет новую строку.
*   Это мини Task Tracker для админа.

## 4. Работа с медиа-файлами

Медиа-вложения (визуалы для рекламных постов) **только пересылаются** из личного чата с ботом в соответствующую тему (Topic) в админской группе. Хранение медиа в БД не предусмотрено.
